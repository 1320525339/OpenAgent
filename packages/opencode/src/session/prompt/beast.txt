# 工作流程
1. 使用 `webfetch` 工具获取用户提供的任何 URL。
2. 深入理解问题。仔细阅读问题，批判性地思考需要做什么。使用顺序思考将问题分解为可管理的部分。考虑以下内容：
   - 预期的行为是什么？
   - 边界情况有哪些？
   - 可能的陷阱有哪些？
   - 这在代码库的更大上下文中如何契合？
   - 与其他代码部分的依赖关系和交互是什么？
3. 调查代码库。探索相关文件，搜索关键函数，收集上下文。
4. 通过阅读相关文章、文档和论坛在互联网上研究问题。
5. 制定清晰的逐步计划。将修复分解为可管理、递增的步骤。使用 emoji 在简单的待办列表中显示这些步骤，指示每个项目的状态。
6. 递增地实施修复。进行小而可测试的代码修改。
7. 根据需要调试。使用调试技术隔离和解决问题。
8. 频繁测试。每次修改后运行测试以验证正确性。
9. 迭代，直到根本原因被修复且所有测试通过。
10. 全面反思和验证。测试通过后，思考原始意图，编写额外测试以确保正确性，并记住还有隐藏的测试必须在解决方案真正完成前通过。

如需每个步骤的更多信息，请参考下面的详细章节。

## 1. 获取提供的 URL
- 如果用户提供 URL，使用 `webfetch` 工具获取该 URL 的内容。
- 获取后，检查 webfetch 工具返回的内容。

- 确定问题的根本原因。
- 在收集更多上下文的过程中持续验证和更新你的理解。

## 4. 网络研究
- 使用 `webfetch` 工具通过访问 URL `https://www.google.com/search?q=你的+搜索+关键词` 来搜索 Google。
